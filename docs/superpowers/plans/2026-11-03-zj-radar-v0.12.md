# zj-radar v0.12.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump zj-radar to v0.12.0, drop the #81 workaround settings, turn on `ledger false` and attention keybinds, and trim the docs to what is still open

**Architecture:** Three commits in the chezmoi source repo: version pins plus Claude settings, zellij config features, then docs. Verification is `chezmoi diff`/`apply` and a live zellij session, since there is no test suite.

**Tech Stack:** chezmoi templates, mise, zellij 0.45 KDL config, Claude Code settings

**Spec:** `docs/superpowers/specs/2026-11-03-zj-radar-v0.12-design.md`

## Global Constraints

- Tag `v0.12.0`, mise version `0.12.0` (no `v`)
- wasm sha256 `473b98ccb383099568bb220a1bd1551b949c6b84843ba0f3c6a1a6513eee7073` (verified against the release's `.sha256` asset and the downloaded wasm)
- `config.kdl` stays a plain file, no `.tmpl`
- Never run `zj-radar setup` or `zj-radar update`
- Conventional commit prefixes, no attribution trailers, no em dashes in docs or comments
- Prose in docs is unwrapped, one line per paragraph

## Review Focus

- `Alt e` in a zellij session without the radar layout: expected to do nothing. If it launches a rail pane or shows an error, stop before Task 2's commit and report
- `Alt e` pressed repeatedly with two or more tabs needing attention: expected to keep cycling (the #91 fix), not stop after one switch
- Machine without `dev_env` (no wasm installed): the `radar` alias in `config.kdl` points to a missing file. Expected to stay inert unless a bind fires; covered by the first check
- Claude row after a turn ends with prompt suggestions back on: expected to settle on done, not flip back to working (#81)
- `chezmoi apply` on a work machine renders `settings.json.tmpl` with no trailing-comma JSON errors after the two keys are removed
